## Что представляет собой этот форк

Singularity — это полноценный форк, а не просто переименование готовой сборки. Он сохраняет весь runtime upstream (нативный движок Bionic, glibc-загрузчик, системные шимы, интерфейс WebView, OAuth, терминал, рабочие пространства) и модифицирует только те компоненты, которыми форк должен владеть самостоятельно:

| Область | Upstream | Singularity |
| :--- | :--- | :--- |
| Имя приложения | Antigravity для Android | **Singularity** (`Singularity Dev` для dev-сборок) |
| Идентификатор пакета | `com.agy` | `dev.singularity.antigravity` (`.dev` для dev-сборок) |
| Порт движка | 45157 | **45167 / 45168**, чтобы оба приложения могли работать одновременно |
| Порт шлюза | 45160 | **45170 / 45171** |
| Подпись APK | общий отладочный ключ | **собственный релизный ключ**, строгая проверка в CI |
| Версия Region bypass | поставлялась | **удалена** — флаг `--region-bypass` завершает работу с ошибкой |
| Доступность моделей | фиксированная таблица | **считывается напрямую из встроенного бинарника**, поясняется для каждой строки |
| Обновления | ручное скачивание APK | **встроенный апдейтер** через GitHub Releases этого репозитория |
| Отслеживание upstream | ручное | расписание GitHub Actions, создающее проверочные PR |

Установка Singularity не затрагивает существующую установку Antigravity: используется другой идентификатор пакета, другие порты, отдельный ключ подписи и изолированная директория данных.

## Доступность моделей — как это работает на самом деле

Singularity никогда не выдумывает несуществующие модели и не делает вид, что модель доступна, если это не так.

Модуль `modules/engine` считывает каталог моделей **непосредственно из встроенного бинарника движка** во время сборки и упаковывает его в `assets/runtime/engine_info.json`. Пользовательский интерфейс:

* отображает то, что реально поддерживает движок (без жестко закодированных списков моделей);
* помечает строку статусом **«engine»**, если в текущей сборке движка данный идентификатор модели отсутствует в принципе;
* помечает строку статусом **«account»**, если движок знает модель, но выбор заблокирован — это решение принимается серверами Google для авторизованной учетной записи;
* оставляет активные строки без изменений.

Таким образом, модель, отсутствующая в движке (как `gemini-4-hydrogen` в текущей встроенной сборке 2.11.0), честно помечается как требующая более нового движка, а модель, известная движку, но недоступная аккаунту, помечается как ограничение аккаунта. Ни один случай не фальсифицируется, и никакие региональные ограничения или проверки подписки не обходятся.

Подробности и доказательства: [docs/AUDIT.md](docs/AUDIT.md).

## Встроенные обновления

Кнопка **Обновления** открывает панель с информацией об установленной версии, последнем релизе из этого репозитория, списке изменений и размере загрузки. При скачивании обязательно проверяется опубликованный SHA-256 хеш до предложения установки. Сама установка выполняется через системный установщик Android — пользователь может отменить или отложить обновление. Никакие файлы не устанавливаются скрытно, а пользовательские данные (проекты, сессии, токены) сохраняются благодаря неизменности ключа подписи и ID пакета.

## Сборка

```bash
bash tools/gen_keys.sh        # однократно: создает ключ релиза форка (в .gitignore)
bash build.sh                 # -> dist/singularity.apk
bash tools/verify_apk.sh dist/singularity.apk
```

Требования, структура сборочного конвейера и сборка в режиме разработки: [docs/BUILDING.md](docs/BUILDING.md).
Процесс релиза и секреты CI: [docs/RELEASING.md](docs/RELEASING.md).

## Статус

Этапы движка, патчинга, рантайма и сборки полностью проверены в этом репозитории (автотесты + сборка подписанного APK). Поведение на целевом устройстве Galaxy A54 (Android 16) — авторизация, PTY, длительные запуски агента, процесс установки — на текущий момент не проверялось на реальном оборудовании из-за отсутствия устройства или эмулятора в среде сборки. См. [docs/IMPLEMENTATION_PLAN.md](docs/IMPLEMENTATION_PLAN.md) для ознакомления с матрицей тестирования.
